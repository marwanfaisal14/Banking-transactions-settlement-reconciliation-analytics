# تحليل المعاملات البنكية ومطابقة التسويات

مشروع بورتفوليو متخصص في المدفوعات، يربط سجل العمليات بتسويات معالج الدفع، ثم يطابق دفعات التسوية مع كشف البنك.

**كل البيانات تجريبية ومولدة محليًا**؛ لا توجد بيانات عملاء حقيقية أو اتصال ببنك، ولا ندّعي تحقيق وفر مالي أو استرداد أموال فعلي.

[افتح لوحة الويب](https://marwanfaisal14.github.io/Banking-transactions-settlement-reconciliation-analytics/) · [نزّل مصدر تقرير Power BI](powerbi/BankingReconciliation-PowerBI.zip)

مصدر تقرير Power BI بصيغة **PBIP** مضاف داخل مجلد `powerbi`: ثلاث صفحات، و32 عنصرًا مرئيًا، وستة جداول، و21 مقياس DAX، والبيانات مضمّنة. **لا يوجد ملف PBIX بعد**؛ افتح المصدر في Power BI Desktop على Windows، واضغط Refresh وراجع النتائج، ثم اختر Save As بصيغة PBIX. اختبارات ملفات المصدر لا تثبت تنفيذ DAX أو سلامة العرض داخل Desktop.

## محتوى المشروع

- 1,200 عملية بثلاث عملات: الدولار الأمريكي والدرهم الإماراتي والجنيه المصري.
- محرك Python للمطابقة الدقيقة، والاستردادات، والتسويات الجزئية، وفروق الرسوم والتوقيت، والتكرار.
- 12 تحليل SQL مع قاعدة SQLite وملفات نتائج CSV قابلة للمراجعة.
- لوحة تفاعلية فيها فلاتر وبحث وتصدير CSV وقائمة استثناءات بالأولوية والمسؤول والإجراء المقترح.
- 28 اختبار Python، وفحوص فعلية للوحة على المتصفح والموبايل.
- توثيق لقواعد المطابقة والمقاييس والبيانات والافتراضات، ودليل لاستيراد النتائج في Power BI.

## التشغيل

من مجلد المشروع، باستخدام Python 3.12:

```bash
python -m payments_analytics build
python -m unittest discover -v
python -m http.server 8000 --directory docs
```

بعدها افتح عنوان الخادم المحلي في المتصفح. لا يحتاج محرك التحليل إلى تثبيت مكتبات خارجية أو خادم قاعدة بيانات.

## أهم نقطة في التحليل

فرق التسوية بين السجل والمعالج مختلف عن فرق التحويل بين المعالج والبنك. لا يجوز جمع الفرقين كأنهما خسارة واحدة، ولا يجوز جمع العملات المختلفة دون نموذج تحويل معتمد. المعاملات غير المستحقة بعد مستبعدة من نسبة المطابقة، وفروق العملة والهوية تظهر منفصلة.

للتفاصيل ونتائج كل عملة وصور اللوحة: [الوصف الكامل بالإنجليزية](README.md).
